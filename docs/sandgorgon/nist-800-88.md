# NIST SP 800-88 Rev. 2 Compliance

Sandgorgon generates NIST SP 800-88 Rev. 2 compliant sanitization certificates as part of the [decommission workflow](decommission.md). Each certificate documents per-drive sanitization with honest verification status.

## Certificate Fields

Every certificate contains the following fields:

| Field | Description |
|---|---|
| `certificate_id` | Unique identifier (UUID) |
| `issued_at` | ISO 8601 timestamp with timezone |
| `asset_hostname` | Hostname of the decommissioned machine |
| `asset_serial_number` | Hardware serial number from BMC |
| `asset_tag` | Organization-assigned asset tag |
| `asset_make` | Manufacturer (e.g., Dell, HPE, Supermicro) |
| `asset_model` | Model identifier |
| `technician` | Username of the operator who initiated decommission |
| `organization` | Organization name from server configuration |
| `drives` | Array of per-drive sanitization records (see below) |
| `overall_result` | `pass` if all drives verified, `partial` if any unverifiable or failed |
| `notes` | Free-text field for additional context |
| `vigo_envoy_id` | Linked Vigo envoy UUID (if the asset was enrolled) |
| `lifecycle_summary` | Condensed lifecycle data: commissioned date, last convergence, compliance status at decommission |

### Per-Drive Record

Each entry in the `drives` array contains:

| Field | Description |
|---|---|
| `serial_number` | Drive serial number |
| `model` | Drive model |
| `media_type` | `NVMe`, `SSD`, `HDD` |
| `capacity_bytes` | Drive capacity in bytes |
| `sanitization_method` | `Clear`, `Purge`, or `Destroy` (per NIST 800-88 definitions) |
| `sanitization_action` | Specific action taken (e.g., `NVMe CryptoErase`, `ATA Secure Erase`, `TCG Opal Crypto Erase`) |
| `verification_result` | `verified`, `unverifiable`, or `failed` |
| `verification_method` | How verification was performed (see below) |
| `verification_limitations` | Explicit statement of what could not be verified |
| `started_at` | ISO 8601 timestamp when sanitization began |
| `completed_at` | ISO 8601 timestamp when sanitization finished |
| `duration_seconds` | Wall-clock duration |

## Sanitization Methods

NIST 800-88 defines three levels of media sanitization, in order of increasing strength:

### Clear

Protects against simple, non-invasive data recovery techniques. Overwrites user-addressable storage with fixed patterns or issues a firmware-level erase command.

Sandgorgon uses Clear for SATA/SAS drives via the ATA Secure Erase command. This is a single-pass firmware erase that covers all user-accessible sectors.

### Purge

Protects against state-of-the-art laboratory techniques. Makes data recovery infeasible with any known method.

Sandgorgon uses Purge for:
- **NVMe drives** -- Sanitize command with CryptoErase or SecureErase (block erase). The NVMe specification guarantees that sanitize operations are non-interruptible and cover all user data, metadata, and deallocated blocks.
- **Self-Encrypting Drives (SED)** -- Crypto-erase via TCG Opal Media Encryption Key (MEK) rotation. Destroying the encryption key renders all on-disk data unrecoverable.

### Destroy

Renders the drive physically unusable. Includes shredding, disintegration, pulverization, or incineration.

Sandgorgon does not perform physical destruction. If an organization requires Destroy-level sanitization, this must be performed by a technician. A certificate can record the destruction with technician attestation (future capability).

## Verification Honesty Per Media Type

Vigo follows an honest compliance principle: certificates state exactly what was verified and what could not be. No drive type gets a blanket "verified" without proof.

### NVMe: Verified

NVMe drives that support the Sanitize command provide a **Sanitize Log** (Log Page 81h). This log records:
- Whether a sanitize operation completed successfully
- The type of sanitize operation performed
- Progress percentage (during operation)
- Whether the most recent sanitize operation completed without error

Sandgorgon reads the Sanitize Log after the erase completes. If the log confirms successful completion, the certificate records `verification_result: verified` with `verification_method: NVMe Sanitize Log (Log Page 81h)`.

### SED (Self-Encrypting Drive): Verified

TCG Opal self-encrypting drives maintain locking state that is queryable. After a crypto-erase (MEK rotation):
- The locking state transitions confirm the MEK was rotated
- The drive's Opal status shows the previous encryption key is no longer valid

Sandgorgon queries the TCG Opal status after crypto-erase. If the state confirms MEK rotation, the certificate records `verification_result: verified` with `verification_method: TCG Opal locking state`.

### SATA/SAS Secure Erase: Unverifiable

ATA Secure Erase is a firmware-level command with no completion proof. The relevant facts:
- SMART data does not record whether a Secure Erase completed
- The drive reports "ready" after the command finishes, but this is true whether the erase succeeded, partially completed, or silently failed
- There is no ATA log page that records sanitization history

The certificate honestly states this limitation:

- `verification_result: unverifiable`
- `verification_method: Drive responsive post-erase`
- `verification_limitations: ATA Secure Erase provides no completion proof in SMART or ATA logs. The drive accepted the command and responded normally after the operation. This meets NIST 800-88 Clear requirements but cannot be independently verified.`

This is not a failure -- it is an honest statement of the protocol's limitations. Organizations requiring provable sanitization for SATA drives should use drives with SED support or physical destruction.

### Physical Destruction: Verified Only with Attestation

For drives that are physically destroyed, verification requires a human technician to attest that destruction was performed. The certificate records:

- `verification_result: verified` (only if technician attestation is provided)
- `verification_method: Technician attestation`
- `verification_limitations: Verification relies on technician's statement. Sandgorgon did not independently observe physical destruction.`

Without attestation, the record is `unverifiable`.

## Regulatory Cross-References

Sandgorgon certificates support compliance with:

### PCI DSS 9.4 -- Media Destruction

Requirement 9.4.6 requires that hard-copy materials and electronic media are destroyed when no longer needed for business or legal reasons. Sandgorgon certificates provide the documentary evidence that sanitization was performed, including method, date, and verification status.

### HIPAA 164.310(d)(2) -- Device and Media Controls

The HIPAA Security Rule requires covered entities to implement policies and procedures for the disposal of electronic protected health information (ePHI). Specifically:
- **164.310(d)(2)(i)** -- Disposal: procedures for final disposition of ePHI and hardware
- **164.310(d)(2)(ii)** -- Media re-use: procedures for removing ePHI before re-use

Sandgorgon certificates document the sanitization method and result for each drive, providing auditable evidence of ePHI disposal.

### SOX -- Asset Controls

Sarbanes-Oxley requires controls over information systems that affect financial reporting. For organizations where server hardware processes financial data, Sandgorgon certificates document the chain of custody from active use through auditable decommission.

## Certificate Export Formats

Certificates are available in three formats:

### JSON

Machine-readable format containing all fields. Suitable for integration with asset management systems, audit tools, and compliance platforms.

```
GET /api/v1/sandgorgon/certificates/{id}
Accept: application/json
```

### HTML (Print-Friendly)

Standalone HTML page designed for printing and PDF generation. Includes all certificate fields in a clean, professional layout with the organization name, certificate ID, and a signature line for the technician.

```
GET /api/v1/sandgorgon/certificates/{id}.html
```

This page is also accessible from the web UI certificate viewer at `/sandgorgon/certificates`.

### CLI Text

Human-readable text output from the CLI:

```
$ vigocli sandgorgon certificate web-04.prod.example.com

NIST 800-88 Sanitization Certificate
=====================================
Certificate ID:  cert-a1b2c3d4
Issued:          2026-03-29T14:22:00-07:00
Asset:           web-04.prod.example.com
Serial:          MXQ93204RZ
Technician:      dthompson

Drives:
  1. Samsung 980 PRO 1TB (S6B2NJ0T123456)
     Method: Purge (NVMe CryptoErase)
     Result: VERIFIED (NVMe Sanitize Log)

  2. Seagate ST2000NM 2TB (ZHZ6ABCD)
     Method: Clear (ATA Secure Erase)
     Result: UNVERIFIABLE
     Note:   Command issued, drive responsive post-erase.
             ATA Secure Erase provides no completion proof.

Overall: PARTIAL (1 of 2 drives verified)
```

The `--format json` flag outputs JSON to stdout. The `--output <file>` flag writes to a file.
