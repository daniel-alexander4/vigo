# Architecture Decision Records

Short documents capturing significant design decisions and their rationale. Each ADR explains what was decided, why, and what alternatives were considered.

ADRs are immutable in their decision content. If a decision is reversed, write a new ADR that supersedes the old one rather than editing it. Terminology refreshes may be applied in-place with an `**Updated YYYY-MM-DD:**` note in the header that explains what changed — the decision and rationale stay frozen.

## Decisions

- [ADR-001: YAML-only config path](001-yaml-only-config.md) — no API/DB/CLI config writes
- [ADR-002: First-match-wins match block](002-first-match-wins.md) — hostname matching order
- [ADR-003: mTLS everywhere](003-mtls-everywhere.md) — no plaintext gRPC, ever
- [ADR-004: SQLite over Postgres](004-sqlite-over-postgres.md) — single-file database for simplicity
- [ADR-005: Rust agent, Go server](005-rust-agent-go-server.md) — language split rationale
- [ADR-006: HTMX-first web UI](006-htmx-first-ui.md) — server-rendered fragments over SPA
- [ADR-007: Pluggable secrets backend](007-pluggable-secrets.md) — provider interface, never plaintext
- [ADR-008: LWW-CRDT for swarm manifest](008-lww-crdt-manifest.md) — conflict resolution without coordination
- [ADR-009: Idempotent executors](009-idempotent-executors.md) — check-before-act, never blind apply
- [ADR-010: Convergence vs compliance terminology](010-convergence-vs-compliance.md) — distinct concepts, never crossed
- [ADR-011: Agent-driven swarm](011-agent-driven-swarm.md) — agents self-assign via manifest; server pushes manifest CRDT entries on check-in to bridge operator-initiated revokes to isolated envoys
- [ADR-012: Lockbox auto-encrypt-on-write](012-lockbox-auto-encrypt-on-write.md) — drop-and-forget UX, sweep-on-unlock for plaintext written while locked, three-class failure handling with `.failed` rename
- [ADR-013: Multi-member gitback](013-multi-member-gitback.md) — **superseded by ADR-015 before implementation**. Original capability-token + self-certifying-project-ID design layered alongside single-user gitback; absorbed and extended by the unified substrate
- [ADR-014: Puddle primitive](014-puddle-primitive.md) — per-user puddle identity (ed25519 keypair, passphrase-wrapped); peer-pair onboarding over swarm mTLS, manual scp as air-gapped fallback; foundation for ADR-015 and ADR-016
- [ADR-015: Unified gitback substrate](015-unified-gitback-substrate.md) — single substrate for personal-DR and multi-member git on top of puddle; orthogonal `members:` × `dr_scope:` axes; helper-enforced access for non-root users (root retains direct filesystem access by design); plaintext-by-design — confidentiality lives in lockbox
- [ADR-016: Lockbox membership on puddle](016-lockbox-membership-on-puddle.md) — puddle-aware recipient resolution and onboarding; per-envoy age keys preserved for compartmentalization; `lockbox puddle *` / `lockbox standalone *` subtree split
- [ADR-017: No puddle-level revoke](017-no-puddle-level-revoke.md) — puddle-level eviction considered and rejected; shared puddle keypair makes revoke a placebo for adversarial removal, and cooperative removal already has a mechanism (`lockbox leave`); supersedes ADR-016's "eviction is puddle-level" line
- [ADR-018: Puddle rekey](018-puddle-rekey.md) — `rekey-pair` / `rekey` verbs preserve lockbox state across a puddle keypair rotation; 24h graceful window + 5-minute single-use claim codes; deliberately friction-bearing on each surviving envoy (no old-key chain-of-trust shortcut). Gitback founder-rekey picked up under ADR-019.
- [ADR-019: Gitback founder-rekey via anchor-preserving delegation chains](019-gitback-founder-rekey.md) — `project_id` stays anchored to the genesis founder pubkey forever; per-project `DelegationEnvelope` chain bridges retired founder pubkeys to the current signing identity; authority windows close the deposed-founder + antedated-token attacks; `re-invite-all` + `rejoin` mediate cross-puddle member rejoin via fresh OOB capability codes; `re-found` is the escape hatch when the chain hits cap. Five slices, shipped 0.35.18 → 0.35.22.
- [ADR-020: Lockbox is puddle-only](020-lockbox-puddle-only.md) — standalone mode retired in 0.40.0; supersedes ADR-016's standalone branch (recipient-resolution and per-envoy-key decisions stand). Mode 1 (encryption-at-rest, no peers) handled via single-envoy puddle. `WrapMode` enum + dual-mode unlock paths + pairwise-gossip recipient resolution all retire. No migration verb — operators with existing standalone enrollments scrub-and-re-enroll under puddle.
- [ADR-021: Lockbox lifecycle absorbed into puddle](021-lockbox-lifecycle-on-puddle.md) — sibling to ADR-020 in 0.40.0. Lockbox's per-capability lifecycle (`init`, `leave`, `forget <host>`) folds into puddle (`puddle init`/`join` auto-enroll, new `puddle leave`, new `puddle evict <host>`); lockbox subtree shrinks to content-only verbs. Per-envoy `lockbox: true` opt-in retired — lockbox mandatory on puddle membership. Gitback's project verbs unchanged (different granularity).
- [ADR-022: Friendly gitback names (puddle/repo)](022-gitback-friendly-names.md) — `gitback://<puddle-name>/<repo-handle>` layered on the self-certifying hex pid; puddle names are first-come, gossiped-via-traits, ambiguous-on-collision (no auto-tiebreak); the server publishes the fleet name map without arbitrating; `re-found` auto-re-issues the claim (the `supersedes` field carries the rekey-delegation chain). Friendly names are a convenience, the hex pid is the proof — spoofable by squatting, stated loudly. Forking = `clone` + `project init` (GitHub-fork semantics; fork ≠ mirror, history forever). Implemented in 0.42.0; `public_read` is a separate ADR. (0.48.0: `RESOLVE-NAME` falls back to the requesting user's own `name-claim.json` on a fleet-map miss, so a fresh claim resolves from the claiming envoy immediately.)
- [ADR-023: Puddle-wide gitback project adoption](023-gitback-puddle-wide-adoption.md) — **implemented in 0.49.0.** A puddle member envoy auto-adopts the projects its puddle founded at `puddle unlock` time, so `dr_scope: swarm-wide` repos actually reach the puddle's other envoys (before this, `project init` wrote per-user state only on the founding envoy → `HOSTS 1` forever). Widens the `GITBACKPROJECT:` announce to carry `<handle>:<dr_scope>` (the legacy 2-field form still parses during a rolling agent upgrade); the catch-up reactor flushes a world-readable `gitback-announced.json` each tick; `puddle unlock` (the one spot that runs as the user with a freshly-spawned session helper) mints founder-bootstrap state for any announced project where `sha256(local_puddle_pubkey ‖ handle) == pid` and there's no local state, then the existing DR-catch-up reactor pulls the bytes. Founder-current-key only (post-rekey projects use `rejoin`); no new attack surface (self-minting a bootstrap is what `project init` already does).

- [ADR-024: curator — P2P artifact registry](024-curator.md) — **implemented in 0.51.0.** A fifth swarm content subsystem: filecast's content-addressed blob transport + gitback's puddle-keyed identity/access machinery + a thin catalog layer. Artifacts (release binaries, tarballs, `.deb`/`.rpm`, container images, the agent's own self-update binaries) keyed `sha256(founder_puddle_pubkey ‖ name)`, referenced `<puddle-name>/<name>:<tag>` (operator puddle = the implicit default namespace); a single founder-signed catalog entry per artifact (mutable tags, multi-arch `platforms:[{os,arch,blob_sha,size}]`, `recipients:["*"]`-by-default, a `target` scope), re-signed LWW on every change, gossiped P2P + aggregated server-side. **Write side is puddle-members-only** (`vigo swarm curator push/tag/rm/prune/…`, gated by `swarm.curator.enabled` × usercrate `curator: bool` × an unlocked puddle; `vigocli` is the operator front-end onto the same `/var/run/vigo/curator.sock`). **Read side is server-mediated and universal** — every envoy, swarm-enabled or not, resolves `<name>:<tag>` via the server (which enforces `recipients`) then pulls the bytes P2P or relayed from the server, and materializes to `/var/lib/vigo/artifacts/…` + `cache.json`. Documented limits: "restrict access" = per-envoy materialization-gating, not byte-confidentiality (raw DR bytes are root-readable on every `target`-matched envoy — lockbox owns confidentiality); the server owns resolution (outage stops new pulls fleet-wide). Consumers (`artifact:` executor param, Docker Registry v2 shim, agent-self-update accelerator) are post-v1 slices. Supersedes the "Artifact — P2P container image distribution" post-v1 entry (generalized); the deferred public-read-gitback feature is its git-content sibling.
- [ADR-025: stockpile-in-gitback — service-account puddle + ops-puddle ownership](025-stockpile-in-gitback.md) — **approved 2026-05-16, not yet implemented.** Pre-Phase-0 design for the tungol redesign. Vigosrv runtime user gets a service-account puddle identity at `/srv/vigo/puddle/identity.wrapped`, wrapped under a key derived from the existing secrets master key via `HKDF-SHA256(master_key, "vigo-puddle-wrap-v1", per-host-salt)`. Extends ADR-014's per-human puddle primitive to service accounts. A dedicated **ops-puddle** (operator-named, e.g., `alexander4-ops`) collectively owns the stockpile gitback project; founder = first vigosrv; subsequent vigosrvs join via the standard ADR-014 puddle-pair flow. Stockpile distribution becomes a single gitback project (`gitback://<ops-puddle-name>/stockpile`) with `dr_scope: swarm-wide`; every vigosrv pulls and triggers config reload via a gitback-event-driven watcher reusing the existing helper-daemon notification pubsub. `vigocli config publish` switches behavior on deployment shape: standalone writes local-filesystem-and-SIGHUPs (today); tungol commits + pushes to the gitback project and waits for the local watcher to confirm. No backwards-compat bridge with `Hub.SyncConfigToSpokes` — Phase 0 retires that path entirely. Five slices; gates the tungol redesign's Phase 0.
- [ADR-026: Peer-equal admissions over pull-based snapshots](026-tungol-peer-equal-admissions.md) — **approved 2026-05-18, not yet implemented.** Slice 2A of the tungol redesign Phase 2. Replaces Phase 1's in-memory `steorraPins` map with a DB-persisted, signature-verified, peer-replicated LWW-Map CRDT (`tungol_members` table, keyed `(tungol_id, steorra_id)`). New admin RPC `PullTungolSnapshot` exposed on every vigosrv; each steorra runs a 30s pull loop against every known peer, merges on LWW `(updated_at, updated_by)`. Hub-seeded peer discovery plus gossip-of-gossip — new steorra learns peers from the hub's first response, subsequent pulls exchange `known_peers` bidirectionally; operator-declared `tungol.peers:` accepted as additive seeds. Every entry Ed25519-signed by `updated_by` using the Phase 1 per-steorra identity; receivers verify against pinned pubkey on merge. Audit events `tungol_steorra_admitted` / `tungol_steorra_revoked`. Hub remains the bootstrap-discovery rendezvous in 2A — write-coordination is peer-equal, but `RoleHub`/`RoleSpoke`/`RoleStandalone` stays as architectural marker until later slices. Out of 2A scope: vigocli `invite`/`approve`/`revoke`/`leave` verbs, consumed-tokens G-Set (2B), license attestation observability (2C), full multi-vigosrv test harness (2D), manifest.go generalization, Tier-2 5m roster snapshot.
