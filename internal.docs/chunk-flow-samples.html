Chunk Flow — 7 Alternatives

Synthetic 7-node swarm. vigosrv is the seed source. Peers have 100 chunks each, drawn from the seed and each other in varying proportions. Colors use the Catppuccin Mocha palette (same 24-slot tiered system the real swarm viz uses).

1. Source × Target Matrix Heatmap

Rows = sources (who served). Columns = targets (who received). Cell color = source-peer color; intensity = chunks transferred. Scales to 50+ peers without layout jank. Closest replacement for Sankey's "who served whom" answer.

2. Chord / Circular Flow Diagram

Peers on a circle, curved edges through the center sized by chunk count. Emphasizes P2P symmetry; gets crowded past ~30 peers. Edge color = source.

3. Stacked Bar per Downloader

One normalized bar per receiving envoy, segments colored by source. Simplest of the lot — reads as "envoy A got 60% from vigosrv, 40% from web01." Could replace both the Sankey and the lower "Chunk Sources by Envoy" strips.

4. Per-Envoy Donut Grid

Small donut per downloader showing source share. Scales well — each donut stays readable independent of fleet size. Center number = total chunks.

5. Force-Directed Network Diagram

Directed graph with a small vanilla-JS force simulation (no D3 here). Edge thickness = chunks, arrow = direction. Natural for "topology" framing. Needs layout stability across HTMX re-renders in production.

6. Ranked Adjacency List

No chart — just sorted rows. Dense, scannable, no layout concerns. Good fallback view for very large fleets or when the palette overflows.

7. Time-Banded Swimlanes

X = time (fabricated for this mockup), one lane per downloader, tick colored by source. Answers "when did chunks flow," which the Sankey doesn't. Requires per-chunk timestamps in ChunkSources — not captured today.
