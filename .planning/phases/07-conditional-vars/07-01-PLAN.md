<feature>
  <name>Conditional Var Evaluation Engine</name>
  <files>server/conditionals/conditionals.go, server/conditionals/conditionals_test.go</files>
  <behavior>
    Conditional var YAML structure (parsed as map[string]any by yaml.v3):
    ```yaml
    is_debian:
      trait: os.distro
      only: [debian, ubuntu]
    ```

    Types and functions:
    - `ConditionalVar` struct: Trait (string, dot-path), Operator (string), Operand (any)
    - `IsConditionalVar(v any) bool`: Returns true if v is a map with "trait" key (distinguishes from regular string vars)
    - `ParseConditionalVar(name string, raw map[string]any) (ConditionalVar, error)`: Validates exactly one operator present, valid operator name, trait field required
    - `Evaluate(cv ConditionalVar, traits map[string]any) bool`: Resolves trait dot-path, applies operator, returns bool

    Operator semantics:
    - `only` ([]any): trait value must be in the list (string comparison). True if match found.
    - `not` ([]any): trait value must NOT be in the list. True if no match found.
    - `gt` (numeric): trait value > operand. Trait and operand coerced to float64.
    - `lt` (numeric): trait value < operand.
    - `gte` (numeric): trait value >= operand.
    - `lte` (numeric): trait value <= operand.
    - `match` (string): trait value matches regex. Regex compiled from operand string.

    Dot-path resolution (trait: "os.distro"):
    - Split on "." and walk nested map[string]any
    - Missing key at any level -> return nil (trait not found)
    - Trait not found -> Evaluate returns false for all operators

    Edge cases:
    - `only: [debian, ubuntu]` with trait "debian" -> true
    - `only: [debian, ubuntu]` with trait "centos" -> false
    - `not: [windows]` with trait "linux" -> true
    - `gt: 4096` with trait 8192 -> true
    - `gt: 4096` with trait 4096 -> false (strict greater than)
    - `gte: 4096` with trait 4096 -> true
    - `gt: 4096` with trait "not-a-number" -> false (non-numeric coercion fails silently)
    - `match: "^ubuntu"` with trait "ubuntu-22.04" -> true
    - `match: "[invalid"` -> ParseConditionalVar returns error (compile regex at parse time)
    - Missing trait -> false for all operators
    - No operator field -> ParseConditionalVar returns error
    - Multiple operator fields -> ParseConditionalVar returns error
    - Missing trait field -> ParseConditionalVar returns error

    Numeric coercion: traits come as any from JSON unmarshal. Could be float64 (from JSON), int, string. Use fmt.Sprintf + strconv.ParseFloat for universal coercion. Operands from YAML could be int or float64.
  </behavior>
