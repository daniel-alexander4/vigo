```go
package conditionals

// ConditionalVar represents a parsed conditional variable definition.
type ConditionalVar struct {
    Name     string
    Trait    string   // dot-path like "os.distro"
    Operator string   // only, not, gt, lt, gte, lte, match
    Operand  any      // []any for only/not, float64 for numeric, *regexp.Regexp for match
}

// IsConditionalVar returns true if the value is a map with a "trait" key,
// distinguishing conditional vars from regular string/scalar vars.
func IsConditionalVar(v any) bool

// ParseConditionalVar parses a raw YAML map into a validated ConditionalVar.
// Returns error if trait field missing, no operator, multiple operators, or invalid regex.
func ParseConditionalVar(name string, raw map[string]any) (ConditionalVar, error)

// Evaluate evaluates a conditional var against a traits map, returning true/false.
// Missing trait -> false. Non-numeric trait with numeric operator -> false.
func Evaluate(cv ConditionalVar, traits map[string]any) bool
```

    - Test: Conditional vars from multiple modules are collected in the resolved ClientConfig
    - Test: Client-level vars do not interfere with conditional vars (conditional vars are not overridable by client vars)

  <action>
    1. In `server/config/types.go`:
       - Add `ConditionalVars []conditionals.ConditionalVar` field to `ClientConfig` (not to ModuleDefinition -- it stays as raw `map[string]any` from YAML, parsing happens in loader)
       - Import the conditionals package

    2. In `server/config/loader.go` `loadModuleDefs()`:
       - After YAML unmarshal of a ModuleDefinition, iterate `def.Vars` and call `conditionals.IsConditionalVar(v)` for each
       - For conditional vars: call `conditionals.ParseConditionalVar(name, rawMap)` -- if error, return load error (fail-fast validation at config load time, not check-in time)
       - Store parsed ConditionalVar objects on a new `parsedConditionals` map in the loader (or return them alongside the module def)
       - Remove conditional var entries from `def.Vars` so they don't flow into regular var merging (they are NOT template-renderable strings)

    3. In `server/config/loader.go` `resolveEntry()`:
       - When building the ClientConfig, collect ConditionalVars from all modules referenced by this client entry
       - Deduplicate by name (first definition wins, matching var merge behavior)
       - Set `cfg.ConditionalVars` on the resolved ClientConfig

    4. In `server/config/loader.go` `cloneClientConfig()`:
       - Clone the ConditionalVars slice

    5. Write tests in `loader_test.go`:
       - `TestLoadModuleWithConditionalVars`: Write a module YAML with both regular vars and conditional vars, load via NewConfigStore, verify conditional vars are parsed and regular vars remain
       - `TestLoadModuleInvalidConditionalVar`: Write a module with bad conditional var (no trait), verify load fails
       - `TestResolveEntryWithConditionalVars`: Write module + client YAML, verify resolved ClientConfig has ConditionalVars populated

    Implementation detail: The `loadModuleDefs` function returns `map[string]*ModuleDefinition`. To carry parsed conditionals through, add a `ConditionalVars []conditionals.ConditionalVar` field to `ModuleDefinition` (unexported yaml tag `yaml:"-"` since YAML parsing gives us the raw map in Vars, and we parse/move them in the loader). This is cleaner than a parallel map.
