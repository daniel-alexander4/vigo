```go
package compliance

// ComputeStatus determines compliance status for a single client.
// Parameters: lastRun (most recent run or nil), lastSeen time, baseInterval from server config.
// Returns one of: "compliant", "drifted", "failing", "stale", "unknown"
func ComputeStatus(lastRun *RunInfo, lastSeen time.Time, baseInterval time.Duration) string
```

Define `RunInfo` struct with Status string, ChangedCount int32 (avoids coupling to db.Run directly).

`ComputeStatus` logic:
1. If `time.Since(lastSeen) > 2 * baseInterval` -> "stale"
2. If lastRun is nil -> "unknown"
3. If lastRun.Status == "success" and ChangedCount == 0 -> "compliant"
4. If lastRun.Status == "success" and ChangedCount > 0 -> "drifted"
5. If lastRun.Status in ("failure", "partial") -> "failing"
6. Default -> "unknown"

Add `Summary` function that takes a slice of client statuses and returns counts map.

Create `server/grpc/admin.go` implementing ALL IsgovAdmin RPCs. Use the research patterns:

**Core handlers (existing RPCs):**

1. `AddApprovedPattern` -- Hash token with bcrypt, call queries.CreateApprovedPattern, return response. Token comes from request, NOT generated here.
2. `ListApprovedPatterns` -- Call queries.ListApprovedPatterns (already exists in approved_patterns.sql), map to proto ApprovedPattern messages. Mark used=true and include used_by if used_at is non-null.
3. `RevokeApprovedPattern` -- Call queries.DeleteApprovedPattern or add a DeleteApprovedPattern query if missing. Parse UUID from request.id.
4. `ListClients` -- Call queries.ListClients, map to proto Client messages.
5. `GetClient` -- Parse UUID, call queries.GetClientByID, map to proto.
6. `RevokeClient` -- Parse UUID, call queries.RevokeClient.
7. `ForcePush` -- If client_id set, call queries.SetForcePush for that client. If empty (--all), list all non-revoked clients and SetForcePush for each. Return count.
8. `ListRuns` -- If client_id set, call queries.ListRunsByClient. Else call queries.ListAllRuns. Default limit 20.
9. `GetRun` -- Call queries.GetRunByID + queries.ListRunResults, map to proto.
10. `GenerateToken` -- Generate 32 bytes of crypto/rand, hex encode, return as token string.
11. `DryRun` -- Parse client_id, get client hostname from DB, get config from configStore.Get(hostname), compute planned actions by comparing desired state with "current" (report as plan entries), store in plans/plan_results tables, return PlannedAction list.

**Extended handlers (new RPCs from Plan 01):**

12. `AddWebhook` -- Call queries.CreateWebhook with url, secret, events from request.
13. `ListWebhooks` -- Call queries.ListActiveWebhooks, map to proto.
14. `DeleteWebhook` -- Parse UUID, call queries.DeleteWebhook.
15. `GetComplianceSummary` -- List all non-revoked clients, for each get latest run (queries.ListRunsByClient limit 1), compute compliance.ComputeStatus, aggregate into summary. Query compliance_history for 30-day trend.
16. `GetClientCompliance` -- Get client, get latest run, compute status, get compliance history entries.
17. `Rollback` -- Parse client_id, create a run with status "running" and type marker. If run_id provided, list file_snapshots for that run. If file_path provided, get latest snapshot for that file. Set force_push flag so agent picks up rollback instructions on next check-in. Store rollback metadata.
18. `ListPackages` -- Call queries.ListAllPackageAudit or ListPackageAuditByClient if client_id provided.
19. `ListPackageDrift` -- Call queries.ListPackageDrift.
20. `PromoteEnv` -- Read module config via configStore, compute diff between from_env and to_env env_vars blocks, store in env_promotions table, return diff. Does NOT modify files (single config path principle).

**Error handling pattern:** Return gRPC status codes: InvalidArgument for bad input, NotFound for missing resources, Internal for DB errors. Use `status.Errorf(codes.X, "msg: %v", err)`.

**Key pitfalls to avoid:**
- ForcePush must NOT make outbound connections to agents. It sets a DB flag only.
- GenerateToken just generates a random token; it does NOT create an approved pattern.
- PromoteEnv is read-only audit -- it computes and records a diff, never writes config files.
- DryRun stores results in plans/plan_results tables (not runs/run_results).

Add a basic test file `server/grpc/admin_test.go` with table-driven tests for at least GenerateToken (verifies crypto/rand output is hex, correct length) and a unit test for the ForcePush handler logic.
