**In server/grpc/checkin.go -- `configToProtoModules` function:**

1. The `vars` parameter already contains conditional var results as "true"/"false" strings (set by `evaluateConditionalVars` earlier in the CheckIn flow).

2. In the inner loop over `mod.Resources`, before building a `pb.Resource`, call `config.ShouldRunResource(res, vars)`. If it returns false, skip this resource (continue to next).

3. Remove the block that copies `res.When` to `pbMod.When` (lines ~197-199). The `When` field on ResourceConfig will no longer exist after we remove it.

4. After the resource loop, if `pbMod.Resources` is empty (all resources were skipped), do NOT add the module to the output list. This avoids sending empty modules to the agent.

**In server/grpc/checkin_test.go:**

Add tests for the filtering behavior:

- `TestConfigToProtoModulesGoIfAllPass`: Create a ClientConfig with a resource that has `GoIfAllPass: ["is_debian"]`. Call `configToProtoModules` with vars `{"is_debian": "true"}` -> resource is included. Call with `{"is_debian": "false"}` -> resource is excluded.

- `TestConfigToProtoModulesSkipIfAnyPass`: Resource with `SkipIfAnyPass: ["is_windows"]`. Vars `{"is_windows": "true"}` -> excluded. Vars `{"is_windows": "false"}` -> included.

- `TestConfigToProtoModulesEmptyModuleExcluded`: All resources in a module are skipped -> the entire module is excluded from the output.

- `TestConfigToProtoModulesNoConditionalsPassThrough`: Resource with no conditional fields -> always included (backward compat).

Note: `configToProtoModules` is a package-internal function, so tests go in the same package (grpc). The function signature needs to be updated: it currently receives `(cfg *config.ClientConfig, facts, vars map[string]any)`. The vars map already contains conditional var evaluation results, so no signature change needed -- just need to pass `vars` through to `ShouldRunResource` inside the function.

Actually, looking at the current signature: `configToProtoModules(cfg *config.ClientConfig, facts, vars map[string]any) ([]*pb.Module, error)` -- `vars` is already available.
