  <files>server/config/loader.go, server/config/loader_test.go</files>
  <behavior>
    - Test 1: Module YAML with conditional_block loads correctly -- block resources appear in ModuleDefinition.Resources with merged conditionals
    - Test 2: Module YAML mixing plain resources and conditional_block -- all resources present in correct order
    - Test 3: Module YAML with conditional_block + depends_on across block boundary -- loads without error
    - Test 4: Module YAML with conditional_block containing resource-level conditionals -- both sets present on flattened resources
    - Test 5: Module YAML with invalid conditional_block (empty resources) -- returns load error
  </behavior>
  <action>
    Modify loadModuleDefs in loader.go to use FlattenResourceNodes for parsing module resources instead of direct yaml.Unmarshal into []ResourceConfig.

    The approach: instead of `yaml.Unmarshal(data, &def)` which relies on struct tags for the Resources field, use a two-step parse:
    1. Unmarshal the module YAML into a yaml.Node tree
    2. Extract the "resources" sequence node
    3. Call FlattenResourceNodes on its content nodes
    4. Assign the flattened result to def.Resources
    5. Parse remaining fields (name, depends_on, vars) from the yaml.Node normally

    Alternatively, simpler approach: change ModuleDefinition to use custom UnmarshalYAML that handles the resources field specially. Add `UnmarshalYAML(value *yaml.Node) error` to ModuleDefinition that:
    1. Iterates mapping entries
    2. For "resources" key: calls FlattenResourceNodes on the sequence value
    3. For other keys: decodes normally

    Use the custom UnmarshalYAML approach since it keeps loadModuleDefs unchanged (still calls yaml.Unmarshal).

    Add tests to loader_test.go that create module YAML files with conditional_block entries and verify the loaded ModuleDefinition has correctly flattened resources.
  </action>
  <verify>
    <automated>go test ./server/config/... -run "TestLoadModule.*ConditionalBlock|TestConditionalBlock" -v -count=1</automated>
  </verify>
  <done>Module YAML files with conditional_block entries load correctly via loadModuleDefs. Flattened resources have block-level conditionals merged. All existing loader tests still pass.</done>
</task>
