Implement the bootstrap script endpoint, agent binary distribution endpoints, and agent self-update mechanism. This enables zero-touch node enrollment via `curl | bash` and automatic agent binary updates.

Purpose: Completes the deployment story — operators can bootstrap new nodes with one command and keep agents up to date without manual intervention.

Output: Working bootstrap endpoint at /bootstrap, binary download at /api/v1/agent/download/{os}/{arch}, version check at /api/v1/agent/latest, and agent self-update in the daemon loop.

   - Package `bootstrap`
   - `Handler` struct with fields: `serverAddr string`, `caFile string`, `agentDir string`, `version string`
   - `NewHandler(serverAddr, caFile, agentDir, version string) *Handler`
   - `RegisterRoutes(mux *http.ServeMux)` — registers:
     - `GET /bootstrap` -> BootstrapScript
     - `GET /api/v1/agent/latest` -> AgentLatest
     - `GET /api/v1/agent/download/{os}/{arch}` -> AgentDownload
   - `BootstrapScript(w, r)`:
     - Read token from `r.URL.Query().Get("token")` — return 400 if empty

     - Compute SHA256 of each binary in agentDir on first call (cache it)
     - Response: `{"version": "1.0.0", "binaries": {"linux/amd64": {"sha256": "abc..."}, "linux/arm64": {"sha256": "def..."}}}`
     - Or simpler: accept `?os=linux&arch=amd64` query params, return `{"version": "1.0.0", "sha256": "abc...", "download_url": "/api/v1/agent/download/linux/amd64"}`
     - If agentDir doesn't exist or is empty, return `{"version": "", "sha256": ""}` (no update available)
   - `AgentDownload(w, r)`:
     - Extract os and arch from path: `/api/v1/agent/download/{os}/{arch}`
     - Validate os is in [linux, darwin], arch is in [amd64, arm64]
     - Serve file from `agentDir/{os}/{arch}/isogov-agent` using `http.ServeFile`

    - Test: CheckForUpdate returns nil when server version matches current version
    - Test: CheckForUpdate returns nil when server returns empty version (no binaries available)
    - Test: Apply downloads binary, verifies SHA256 checksum, writes to temp file, renames atomically
    - Test: Apply returns error and does NOT replace binary when checksum mismatches
    - Test: Apply returns error when download URL returns non-200
    - Test: Apply cleans up temp file on error
  </behavior>
  <action>
1. Add `var version string` to `agent/main.go` (injected via `-ldflags "-X main.version=..."` at build time). Pass it through to the daemon loop.

2. Create `agent/update/updater.go`:
   - Package `update`
   - `VersionInfo` struct: `Version string`, `SHA256 string`, `DownloadURL string`
   - `CheckForUpdate(ctx context.Context, serverAddr, currentVersion, goos, goarch string) (*VersionInfo, error)`:
     - HTTP GET to `https://{serverAddr}/api/v1/agent/latest?os={goos}&arch={goarch}` (use http since it's the REST API port which may not be TLS in dev — actually use the provided serverAddr scheme)
     - Actually, the agent knows the REST API address. It should be derived from the gRPC server address or provided separately. For simplicity, add a `--api-addr` flag to the agent, or derive from server config. Research says agent checks version during regular check-in. Simplest approach: add the REST API base URL as a field.
     - Parse JSON response: `{"version": "x.y.z", "sha256": "hex...", "download_url": "/api/v1/agent/download/linux/amd64"}`
     - If response version equals currentVersion or is empty, return nil (no update)
     - Return VersionInfo with full download URL constructed from serverAddr
   - `Apply(info VersionInfo, currentBinary string, httpClient *http.Client) error`:
     - Download to temp file in same directory as currentBinary (ensures same filesystem for atomic rename)
     - Stream download while computing SHA256 via `io.MultiWriter(tmpFile, sha256Hash)`
     - Compare computed checksum to info.SHA256 — on mismatch, remove temp file, return error
     - `os.Chmod(tmpPath, 0755)`
     - `os.Rename(tmpPath, currentBinary)` — atomic on same filesystem
     - `syscall.Exec(currentBinary, os.Args, os.Environ())` — replaces process
     - Defer `os.Remove(tmpPath)` for cleanup on any error path

3. Modify `agent/checkin/loop.go`:
   - Add `UpdateConfig` struct: `APIAddr string`, `CurrentVersion string`, passed into `Loop`
   - After a successful convergence run and before sleeping, call `update.CheckForUpdate`
   - If update available:
     - Log "newer agent version available, updating" with version info
     - Get current binary path via `os.Executable()`
     - Call `update.Apply` — if it succeeds, the process is replaced (exec)
     - If Apply fails: log warning, continue running old version, will retry next cycle
   - Pass runtime.GOOS and runtime.GOARCH for platform detection
   - Use `http.Client` with the CA cert for TLS verification (or plain HTTP if API is plain)

4. Modify `agent/main.go`:
   - Add `var version string` at package level (ldflags target)
   - Add `--api-addr` flag (default "http://localhost:8080") for the REST API address used by self-update
   - Pass version and apiAddr into `checkin.Loop` via the UpdateConfig struct
   - Update `Loop` call sites in both `rootCmd` (daemon) and note that `runCmd` (one-shot) does NOT self-update
   - Add a `version` subcommand that prints the agent version

5. Create `agent/update/updater_test.go`:
   - Use httptest.NewServer to mock the version check and download endpoints
   - Test CheckForUpdate with matching version returns nil
   - Test CheckForUpdate with newer version returns VersionInfo
   - Test Apply with correct checksum succeeds (mock the syscall.Exec by using a test helper — since exec replaces the process, test everything up to the exec call by splitting Apply into download+verify and exec steps)
   - Test Apply with wrong checksum returns error and temp file is cleaned up
   - Actually: refactor Apply to take an optional `execFn func(binary string, args []string, env []string) error` for testability. Default to `syscall.Exec` wrapper. Tests pass a no-op or recording function.
